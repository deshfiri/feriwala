Console commands

Every Artisan command this repository defines, the scheduled tasks registered in routes/console.php, the composer and npm scripts, and the stock Laravel, Boost and Wayfinder commands the project relies on.

Note. Run everything in a WSL shell from the repository root. Use php artisan list to see all registered commands and php artisan <command> --help for options. Pass --no-interaction in scripts.

Project commands (app/Console/Commands)

Seven commands, all auto-discovered. None is defined inline in routes/console.php, and the repository defines no other Command subclass.

SignatureClassPurpose and optionsWhen to run, and safety
courier:steadfast-sync {--limit=} SyncSteadfastShipments Asks Steadfast about one bounded batch of parcels that are still moving, through SynchroniseSteadfastShipments. --limit overrides courier.steadfast.poll.batch. Prints counts only (checked, changed, failed), never a payload, address or name. Exit code is failure only when every checked parcel failed. The scheduler runs it every five minutes. Run by hand to catch up after an outage. It does nothing while Steadfast is switched off. Idempotent with the webhook: both apply a status through one locked action. Never books a parcel; see Courier.
bd-locations:import {--mode=import} ImportBdLocationsCommand Imports the bundled Bangladesh location directory (division, district, upazila, union) through ImportBdLocations. Modes: validate (inspects bundled files only), dry-run (runs the upsert inside a transaction that is always rolled back), import (commits and appends a row to bd_location_imports). Also run by SafeSeeder. Upserts by natural key and only deactivates rows it no longer recognises; never deletes. Run --mode=validate first after editing the bundled data. Must run before bd-banks:import so banks can link to districts. See Location.
bd-banks:import {--mode=import} ImportBdBanksCommand Imports the bundled bank and branch directory through ImportBdBanks. Same three modes. Warns about unmatched districts (imported with no bd_locations link). Also run by SafeSeeder, after locations. Re-runnable. See Bank.
partners:assign-numbers {--dry-run} AssignPartnerNumbersCommand Gives every business account without a BJ partner number one (BJ plus eleven digits), including soft-deleted accounts so the register has no gaps. --dry-run counts what would change. Backfill after the add_partner_number_to_business_accounts migration. Safe to re-run: it fills only a missing number, in one statement that re-checks the column, so a number is never replaced and two concurrent runs cannot both assign. Does not touch updated_at. Exit code is failure if any account could not be placed (re-run).
storage:migrate-to-r2 {--mode=inventory} {--chunk=200} {--report=} MigrateManagedFilesToR2Command Moves already-stored local files onto Cloudflare R2 through RunStorageMigration. Modes: inventory (counts only, no disk access), dry-run (adds how many eligible rows miss their local file; no network, no writes), migrate (copies; resumable because rows already on R2 are excluded next time), verify (re-checks every R2 row against its recorded size and checksum; never writes). --chunk is rows per read, --report a path for the JSON report (stdout by default). migrate and verify refuse to run until R2 is configured and switched on under the admin storage settings. Run inventory and dry-run first. See Storage.
catalog:verify-wholesale-pricing {--snapshot=} {--against=} {--allow-explicit-percentage} {--show-values} VerifyWholesalePricingCommand Read-only deployment check that protected prices survive a migration. --snapshot=<file> before migrating records, per row, the exact decimal text PostgreSQL stores (never a float) for the money columns of products and product_variants, plus row, null and zero counts, decimal scales and a checksum. --against=<file> after migrating compares and exits non-zero if anything changed, was nulled, zeroed, re-scaled, missing or duplicated. --allow-explicit-percentage (development only) tolerates a deliberate switch to the Percentage pricing method. --show-values prints before and after text. Run around the deploy that introduces the pricing-method migration. The snapshot is production data: the command refuses to write it inside the repository, public/ or storage/, writes it mode 0600, and prints row ids and categories only unless --show-values is passed. Writes nothing to the database or the log. With neither option it exits as invalid.
wallets:verify-typed-balances {--snapshot=} {--against=} VerifyTypedWalletBalancesCommand Read-only deployment check that typed wallet balances changed no balance. The snapshot records every balance bucket of wallets and supplier_wallets as exact decimal text plus what each ledger holds in total. The comparison fails if any value changed, a wallet is missing, a ledger gained or lost an entry, or a pre-existing balance is anything other than withdrawable. Same snapshot/against workflow and the same protections as the pricing check (outside the release directory, mode 0600). Run around the typed-balances migrations. Nothing is written to the database.

Scheduled tasks (routes/console.php)

Twenty-four tasks, every one with onOneServer() and withoutOverlapping() (guards held in the isolated Redis lock database, §41). They need a scheduler process; see Operations for the full table with cadence and reasons. One of them is a command; the rest call an Action.

NameCadenceWhat it runs
courier:steadfast-sync (command)every 5 minutesThe Artisan command above.
closures named for their task, such as kyc-deadline-sweep, wallet-balance-check, ledger-integrity-check, gateway-reconciliationper taskEach calls an Action's handle() or sweep(). Closures are named because onOneServer() has no command string to key on.
 
php artisan schedule:list        # every task and its next due time
php artisan schedule:run         # what cron runs every minute
php artisan schedule:work        # a local foreground scheduler
php artisan schedule:test        # pick one task and run it now

There is no per-task Artisan command for the closures. To fire one by hand, use schedule:test or call the Action from tinker; every sweep is idempotent under row locks.

php artisan dev

Composite command from the framework (Illuminate\Foundation\Console\DevCommand), run by composer dev. It multiplexes php artisan serve, php artisan queue:listen --tries=1 --timeout=0, php artisan pail --timeout=0 (when pcntl and Pail exist), npm run dev and, registered by Reverb, php artisan reverb:start. On Windows it uses concurrently; elsewhere @laravel/multiplex.

OptionEffect
-s, --streamStream mode.
-t, --tabsTabs mode (the default).
-i, --inlinePrint inline instead of rendering the TUI (the default when not a TTY).
--timestampsTimestamp each line.
--no-restartDo not auto-restart a crashed process.
--jsonNewline-delimited JSON events; implies --inline.
--buffer-size=, --stream-buffer-size=Output buffer limits.

php artisan dev:list prints the registered processes. The scheduler and queues other than default are not started; see Getting started.
