Frontend

The ERP interface is Inertia v3 and React 19 with Tailwind 4, in resources/js. This page covers the folder layout, how pages and layouts are resolved, Wayfinder, the shared components (DataTable, StatusPill, MoneyAmount, MoneyInput, state components), translations, design tokens and the admin-selectable accent, the vendored shadcn ui/ folder, and how to test and check the front end.

Pages and layouts

The layout is chosen by page name in app.tsx, not by each page:

Page nameLayout
welcome, supplier/auth/login, supplier/auth/registerNone (they draw their own full-screen two-panel shell).
auth/*AuthLayout
supplier/auth/*SupplierAuthLayout
supplier/*SupplierLayout (visibly separate from the ERP, D25)
settings/*[AppLayout, SettingsLayout] (nested)
everything elseAppLayout

A page can set its own breadcrumbs with Page.layout = { breadcrumbs: [...] }. Known debt: breadcrumb titles are hard-coded English in 15+ pages (.ai/rules/ui-surfaces.md); do not translate them piecemeal.

Skeletons: lib/page-shape.ts learns a screen's shape (list, dashboard, form, detail) after it first renders and remembers it against the URL pattern, so no page hand-draws a skeleton and the next visit is drawn in the right shape.

Inertia v3 features are all available (deferred props, prefetching, optimistic updates, useHttp, layout props). When using deferred props, give them an empty state with a pulsing skeleton. Activate the inertia-react-development skill when working on client-side Inertia patterns.

Wayfinder (@/actions, @/routes)

Wayfinder generates typed functions from Laravel routes. Never hardcode a URL; import it.

import { show } from '@/routes/wallet';                       // by named route
import { create as topUp } from '@/routes/wallet/top-up';
import WalletTopUpController from '@/actions/App/Http/Controllers/Erp/WalletTopUpController';  // by controller

<Link href={show()}>...</Link>
<Form {...WalletTopUpController.store.form()}>...</Form>
  • Generated into resources/js/actions, resources/js/routes and resources/js/wayfinder, all git-ignored. The Vite plugin (wayfinder({ formVariants: true })) regenerates them during npm run dev / composer run dev.
  • Manual regeneration: php artisan wayfinder:generate --with-form. Always --with-form: without it the .form helpers vanish and tsc --noEmit fails in ~40 unrelated files with Property 'form' does not exist (.ai/rules/actions.md).
  • A new backend route is unknown to TypeScript until regenerated. Activate the wayfinder-development skill for details.

Shared components

DataTable

components/data-table/data-table.tsx is the one list component (it backs roughly fifty screens); reuse it, do not write a table. It covers search, filters, sorting, server-side pagination, column visibility, bulk actions, export, and every state (ready, loading, error, forbidden, plus empty). Key props: columns: Column<T>[] (key, header, cell, sortable, priority: 'primary'|'secondary', hiddenByDefault, alwaysVisible), paginator: Paginator<T> (Laravel's length-aware paginator shape), rowKey, state, searchable, filters, actions, selection + bulkActions, renderCard (mobile cards below md instead of sideways scroll), renderTile (list/tile switch), viewStorageKey, emptyState, onRetry, onlyReload.

  • hooks/use-table-query.ts keeps search, sort, filters and page in the URL (bookmarkable, survives refresh and back) and asks the server; the browser only ever holds one page of rows (§39). Nothing polls. Pass only so a filter change re-fetches the table and nothing else.
  • On the server, return a paginate() result and honour search, sort, direction query parameters in the Query class.

StatusPill

components/status-pill.tsx takes tone, a required label and optional icon. Tones are five: success, warning, danger, info, neutral (lib/status.ts), each with a default icon and a hairline border, so status is never conveyed by colour alone (§33.9). Map every status of every module onto those five tones; do not invent hues. Get the label from the server enum's label().

MoneyAmount and MoneyInput

  • components/money-amount.tsx: renders the server's Money JSON ({amount, currency, formatted}, type in lib/money.ts), always tabular-nums, with title carrying the exact decimal. Pass direction explicitly ('credit' | 'debit' | 'neutral'): ledger rows store a debit as a positive amount with a debit type, so inferring from the sign colours half a statement wrongly. showSign and size (small|default|large) are optional.
  • components/money-input.tsx: labelled input with a symbol (default Taka) that submits the decimal string exactly as typed, uncontrolled, never a minor-unit integer. components/forms/money-field.tsx is the unlabelled variant for use inside FormField.
  • lib/money.ts offers only string-pattern predicates (isZero, isNegative, isPositive, directionOf, signed). Nothing in React parses, multiplies or divides an amount. A guard test fails the build on .decimal reads, _minor names and minor_units in resources/js (see Conventions).

States

Every important screen needs loading, empty, error and permission-denied states (§33.10). They are in components/states/: EmptyState (nothing yet, an invitation to create), ErrorState (retry), PermissionDeniedState, OfflineState, TableSkeleton, PageSkeleton, with StateShell as the common frame. DataTable already renders them.

Surfaces and forms

  • PageContainer owns the gutters (16px on a phone, 24px from sm) and vertical rhythm; every authenticated screen opens with it. width="narrow" for forms and detail panels, default full for tables and dashboards. Do not hand-roll space-y-6 p-4.
  • SectionCard is the panel (title, description, actions, footer; headingLevel; tone="destructive"). StatCard/StatCardGrid for figures, passed already formatted by the server. DetailList/DetailItem for label-value pairs. Notice for tinted explanatory boxes. NativeSelect and Textarea match Input.
  • Forms: FormField, SubmitButton, InputError, ReasonTextarea, ReasonDialog, ConfirmDialog, FileField in components/forms/. Mutations that need a reason use the reason dialogs (lib/reasons.ts).
  • Radius is a token (--radius 8px; rounded-xl 12px, rounded-2xl 16px), never a per-screen choice. Status hues (text-warning, text-danger) are used on their own -subtle ground; do not reach for a Tailwind palette colour.
  • Charts (components/charts, lib/chart.ts): plain SVG, measured with useMeasuredWidth. A ChartPoint carries value (plottable) and formatted (server-written string); tooltips print formatted. Money axes take server-formatted ticks. Series colour is tone: 1..5 mapped to --chart-1..5, never a hex. Gaps stay gaps. A chart never carries meaning in colour alone.
  • Navigation: hooks/use-navigation.ts builds the sidebar from permissions (usePage().props.permissions) and account presence. Everything under "My business" needs account to be present, because platform staff have none. See the shared-prop gotchas in HTTP layers.

Translations

hooks/use-translation.ts returns { t, locale, direction, available } from the shared translations and locale props.

const { t } = useTranslation();
t('common.actions.save');                       // lang/en/common.php  ->  ['actions' => ['save' => ...]]
t('common.table.showing', { from: 1, to: 25, total: 25 })  // ":name" placeholders, same syntax as Laravel
  • A missing key returns the key itself, on purpose: a visible common.actions.save is a bug somebody fixes; an empty string is a blank button nobody notices.
  • Placeholders are replaced in one pass, longest token first, so :to never matches inside :total.
  • Every user-facing string goes through t(), with lines in lang/en/*.php and lang/bn/*.php. The server ships the whole active-locale tree (English fallback) as the lazy translations prop, so a new lang file needs no front-end wiring. Status labels come from the backend enum (HasTranslatedLabel).
  • direction comes from the locale; syncDocumentLocale keeps <html> in step after each visit.

Design tokens and the brand accent

Tokens live in resources/css/app.css (@theme at the top, :root for light, .dark for dark, @custom-variant dark (&:is(.dark *))). The approved direction is a neutral warm-grey surface with near-black primary actions and one restrained orange accent (D6). Never put a colour directly in a component; use a token class (bg-card, text-muted-foreground, bg-brand, text-success, bg-success-subtle, text-credit, text-debit, --chart-1..5).

  • Accent. Every brand token derives from --brand-base (default #ca6330): --brand, --brand-foreground, --brand-subtle, --brand-border, with --brand-on and --brand-lifted-on chosen for text contrast (4.5:1 minimum, lib/accent.ts). Buttons and navigation have their own triples (--button-base, --nav-base ...).
  • Admin-selectable. Under Admin → Branding (Admin\BrandingController, App\Domain\Settings\Branding) an admin picks a preset (orange, crimson, amber, emerald, teal, blue, indigo, violet, slate: ACCENT_PRESETS) or a custom #rrggbb. The server shares branding; components/branding-head.tsx writes the properties onto document.documentElement client-side.
  • Painted before hydration. resources/views/app.blade.php paints the canvas colour inline before the stylesheet loads. Those values mirror --background for each theme; if you change the token, change them. tests/Feature/Ui/AppearanceShellTest.php fails if they drift.
  • Appearance is exactly Light, Dark and System. No fourth palette. The choice is stored in localStorage and a cookie (appearance, exempt from encryption in bootstrap/app.php).

Vendored shadcn ui/

Do not hand-edit resources/js/components/ui. It is vendored shadcn; it is excluded from lint and formatting. The few defaults that do not match the palette (dialog overlay, surface, corner) are corrected at the bottom of app.css against the data-slot each primitive stamps ([data-slot='dialog-content'], ...). Skin by data-slot or wrap the primitive in an app component.

Gotchas from the rules

  • HTML pattern with a hyphen. pattern="^[a-z0-9-]+$" throws "Invalid regular expression" in current Chrome (Unicode Sets mode) and can abort in-flight form handling. Escape it (\\- in a JS string) or drop the client pattern and rely on server validation + InputError.
  • Derived "kind" values must be React state. In a dialog where a <select> changes which fields render, never compute const kind = x ?? y once and leave the select uncontrolled; use useState seeded from props and a controlled select.
  • Never rebuild assets while the PHP suite runs. Deleting public/hot or running npm run build mid-run makes every Inertia response test fail with ViteException (.ai/rules/tests.md). Build before starting the suite; a new page is missing from the manifest until built.
  • If a front-end change does not show, you probably need npm run dev, composer run dev or npm run build.
  • A page prop must not be named like a shared prop (account, auth, locale...). See HTTP layers.

How to add a screen

  1. Make the backend route and controller (HTTP layers); regenerate Wayfinder with --with-form.
  2. Create resources/js/pages/<area>/<name>.tsx; its default export is the page, props typed from @/types. The layout is automatic.
  3. Open with PageContainer; group content in SectionCard; use DataTable for lists with useTableQuery; render money with MoneyAmount (explicit direction), status with StatusPill.
  4. Provide loading, empty, error and permission-denied states from components/states.
  5. Put every string in lang/en and lang/bn and read it with t().
  6. If it is a menu item, add it to use-navigation.ts and its ability to HandleInertiaRequests::NAVIGATION_ABILITIES.
  7. Add a Vitest test for non-trivial logic, run npx vp check --fix <files> and npm run types:check.
