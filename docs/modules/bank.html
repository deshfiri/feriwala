Bank module

The Bangladesh bank and branch directory: banks keyed by BEFTN bank code, branches keyed by nine-digit routing number and linked to the location directory by district. It feeds the bank-account payout-method form; withdrawals read the chosen bank by name.

Purpose

Payout methods (Payout) for a bank account must name a real bank and branch, not free text. This module holds that reference data, bundled in the repo (database/data/bangladesh-bank/NOTICE.md), imports it with validation, and serves cached lookups. Users: partners and Suppliers choosing where money is sent; the system (import).

Key terms

Bank code
Three-digit BEFTN code, unique; the public identifier for a bank.
Routing number
Nine digits, globally unique, its first three digits equal the parent bank's code; the public identifier for a branch.
Payable
Nullable boolean on a bank. null means the source could not identify the institution (e.g. code 050), which is distinct from false.
Selectable
Active, payable === true and available_in_selector (BdBank::isSelectable()).

Reference data like bd_locations: never deleted, deactivated when absent from a later import. No public ULIDs; the bank code and routing number are the public identifiers.

States & lifecycle

Active or inactive only. A branch's district stays nullable: a branch that cannot be matched is imported anyway and reported as unmatched, not dropped.

Actions & workflows

ImportBdBanks::handle($mode)

  1. Reads three bundled files: bangladesh_bank_branches_website.json (bank-level fields: payable, aliases, available_in_selector, branch_count, and banks with zero branches), bangladesh_bank_branches_flat.json (canonical branch rows) and bangladesh_bank_branches_audit.json (only its issue count is reported).
  2. Refuses to import if meta.generated_utc disagrees across the three files.
  3. Parses banks and branches; resolves each branch's district to bd_locations by normalized name (uppercase letters only) with the reviewed DistrictAliases (BARISHAL→BARISAL, CUMILLA→COMILLA, JHALOKATI→JHALAKATHI). A name in neither is reported as unmatched, never assigned to the closest-looking district.
  4. validate stops there; dry-run runs the same upsert in a transaction that is always rolled back; import commits the upsert and appends a bd_bank_imports row.

Run the location import first, since branches resolve against it. BdBankLookups (cached 1 day, key bd_banks.v{importId}.{scope}.{key}):

  • selectableBanks(): active, payable = true, available_in_selector = true, ordered by name; returns bank_code, name, slug.
  • branchesFor($bankCode, $districtLocationId): active branches of an active bank in one district, ordered by name; returns routing_number, name, branch_code. Empty if the bank or district does not resolve.

Permissions & scoping

Reference data with no owner; the lookups need only authentication. No admin screen or permission edits banks.

Money, ledger & audit effects

None. The directory holds no balances. Its use in money flows: PayoutMethod carries bd_bank_id and bd_bank_branch_id as real foreign keys (only for PayoutMethodType::BankAccount; SavePayoutMethod nulls them for bKash and Nagad). The account holder, account number and account type stay in the encrypted details blob, since which bank a method uses is not itself sensitive. When a withdrawal is requested (RequestAccountWithdrawal, RequestSupplierWithdrawal), the payout method is frozen into payout_snapshot via PayoutMethod::toSnapshot(), which includes bankName; a later change to the bank row does not rewrite that withdrawal. On erasure the snapshot is blanked. See Payout and Withdrawal.

Configuration

None. Source files and notice are in database/data/bangladesh-bank/.

Rules, invariants & gotchas

  • Mobile payout requests send bank_code and branch routing_number; the request resolves both to active rows and rejects a branch that does not belong to the bank (payout.form.invalid_bank_branch).
  • A bank with payable = null or available_in_selector = false is invisible to the selector even though it exists.
  • Never extend DistrictAliases by guessing; only reviewed differences belong there.
  • Import order: locations, then banks. A re-import changes the cache version, so lookups refresh by themselves.
  • Mismatched generation timestamps across the three files abort the import deliberately.

How to…

Refresh the bank directory

  1. Replace the three JSON files in database/data/bangladesh-bank/ and update NOTICE.md.
  2. php artisan bd-banks:import --mode=validate, then --mode=dry-run, then default. Read the unmatched districts warning.
  3. If a district legitimately renamed, add a reviewed alias to DistrictAliases::MAP (normalized keys).

Offer a bank in the selector

  1. It needs payable = true and available_in_selector = true in the source data; there is no admin switch.

Testing

Pest group bank: vendor/bin/pest tests/Feature/Bank in its own schema, one suite at a time. ImportBdBanksTest feeds decoded arrays to handleDecoded() instead of the 8,000-plus real rows.
