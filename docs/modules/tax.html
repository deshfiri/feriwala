Tax engine

A configurable tax engine (D19): versioned rates, scoped rules, dated exemptions, and one class, TaxEngine, that every priced charge asks. Exclusive is the default; inclusive is supported. No statutory rate is hardcoded.

Purpose

Fees, wholesale goods and delivery must carry tax that an invoice can show per rate and a tax return can reconcile. D19: tax-exclusive by default, admin-configurable rates, product, category and fee rules, exemptions, effective dates, tax breakdown on invoices. Final Bangladesh VAT rates and Mushak format are to be confirmed with an accountant before launch; the migration seeds no rate.

Used by admin staff (configure under Admin, Billing) and by the system (every quote). Spec: §9. Decision: D19, with D26 for exact money.

Key terms

Rate
A named percentage valid for a period, identified by a code (for example vat-standard). Several rows share a code, one per period. Held in basis points: 1500 is 15.00%.
Rule
Says which rate code applies to what (scope and value), in which mode, from when. Points at a code, never a row.
Mode
exclusive (tax added on top; the amount is net) or inclusive (tax already inside; the amount is gross).
Scope
everything, fee, category, product, in increasing specificity.
Exemption
A dated grant with a reason, for one account.
Breakdown
Tax grouped by rate: net, tax, gross per line; what an invoice and a return need.

Data model

Table / modelColumns and constraints
tax_rates / TaxRatepublic_id, code (max 64, lower-cased on write), name, rate_basis_points (unsigned integer), effective_from, effective_until, is_active. Unique (code, effective_from). Constants BASIS_POINTS_PER_PERCENT = 100, BASIS_POINTS_WHOLE = 10000. Overlap of two open windows for one code is refused in code, not by the database.
tax_rules / TaxRulepublic_id, scope, scope_value (a string, not a key), tax_code, mode (default exclusive), priority (0 to 65535), window, is_active, note.
tax_exemptions / TaxExemptionbusiness_account_id, reason (required), certificate_reference, window, granted_by, revoked_at, revoked_by. Revoked rather than deleted.
payment_tax_lines / PaymentTaxLine (Billing)Per payment and rate: code, label, basis points, mode, taxable_amount, tax_amount, currency. Copied from TaxCharge::toPaymentLine().

Rates and rules are versioned, never edited: closing sets is_active = false and an end date (now() if none), so a charge resolved against an earlier moment still finds the rate then in force. The monetary columns of payment_tax_lines were originally _minor bigints and were converted to flat Taka by the D26 migration.

States & lifecycle

There is no status enum. A rate or rule is open (is_active and inside its window) or closed. Every effectiveAt($at) scope tests is_active, effective_from <= at and effective_until null or after at. An exemption is in force until revoked_at is set or its window ends.

How a charge is worked out

  1. Zero amount: no tax.
  2. charge() only: a fee type that is not taxable (AllocationType::isTaxable(), which excludes the wallet deposit, tax, gateway charge and discount) is not taxed.
  3. An account with an exemption in force at $at: no tax.
  4. Find the rule. For charge() the chain is the requested scope then everything; for goods it is product, categories, then everything. The first level with a match wins outright; within a level, higher priority then higher id wins. Priority never crosses levels, so a broad high-priority rule cannot override a targeted one. Scope values compare case-insensitively.
  5. No rule: no tax (D19 forbids assuming a rate). A rule whose code has no rate in force on that date also charges nothing, but logs a warning Tax rule matched a code with no rate in force. because that is a misconfiguration. A zero-rate rate charges nothing.
  6. The rate is found by code and date (latest effective_from wins if windows overlap), not by row id.
  7. Apply in the rule's mode.

Exclusive and inclusive arithmetic

ModeGivenComputation
Exclusivenettax = net.percentage(rate, HalfAwayFromZero); gross = net + tax.
Inclusivegrossnet = round(gross × 10000 ÷ (10000 + bps)) at 20-digit working precision, half away from zero; tax = gross − net. The tax is the remainder, so net plus tax always equals the price shown.

Example: 500.00 at 15% inclusive gives net 434.78 and tax 65.22. Exclusive at 15% gives tax 75.00 on a net of 500.00.

Allocation to lines and exact reconciliation

  • Discount before tax: both quotes share a coupon discount across the taxable lines with Money::allocate() (CalculateActivationQuote::afterDiscount across fee types; PriceCheckout::shareDiscount across cart lines), then tax each line on what it actually sells for. Ratios are integer counts of the currency's smallest unit; if the product would overflow an integer, weights are scaled down to millionths of the subtotal. Because allocate() hands out remainder units, the shares sum back to the discount exactly.
  • TaxBreakdown::of() merges charges with the same code|basis points|mode (two fees at the standard rate become one invoice line) and drops zero-tax charges, so an invoice never lists "0% — 0.00".
  • addedTotal() is the exclusive tax that joins the payable total; includedTotal() is inclusive tax already inside prices (shown, reported, never added again); total() is both; taxableTotal() sums net.
  • The quote's single tax allocation holds only the added total; the per-rate detail goes to payment_tax_lines in the same transaction as the payment.
  • Delivery is taxed with scope fee and value wholesale_delivery (FeeType::WholesaleDelivery) in PriceCheckout.

Permissions & scoping

Behind the Billing policy: payment.view to see, payment.manage_settings to change (see Billing). Tax configuration is global, not per account; the only per-account element is an exemption.

Money, ledger & audit effects

No ledger entry. Audit actions (all module: payment, sensitive): tax.rate_created, tax.rate_closed, tax.rule_created, tax.rule_closed. Invariants: net plus tax equals gross in either mode; discount shares equal the discount; the stored tax lines are copies, so changing a rate later never changes an issued invoice.

Configuration

No env or config keys. All of it is data (tax_rates, tax_rules, tax_exemptions). With none configured the system charges no tax.

Rules, invariants & gotchas

Gotcha: product and category rules match SKU and slug. The migration comment says a product rule holds a public id, but TaxEngine::chargeGoods() and PriceCheckout pass $product->sku and category slugs, compared case-insensitively. Write rules to match what the engine passes.

Gotcha: a missing rate is silent on screen. A rule naming a withdrawn code looks fine in settings and charges nothing. createRule refuses a code that never existed, but cannot catch one closed afterwards; watch the warning log.

  • Exclusive is the default so a fee configured at 500 stays 500 of revenue; switching a rule to inclusive would turn it into 434.78 revenue at 15%.
  • createRate validates 0 to 10000 basis points, end after start, and refuses a second open window for the code. createRule refuses a tie (same scope, value, priority and overlapping window). Both take row locks for the check.
  • TaxRate::percent(), formattedPercent() (uses number_format) and TaxCharge::rate() return floats for display only. Never use them in a calculation.
  • I found no Action or route that grants or revokes a TaxExemption; only the factory and the engine's read. Treat exemptions as read-only in the app until one is built.
  • Rates are looked up by the date of the charge. Pass the original $at when reissuing or refunding so the arithmetic is reproduced.

How to…

Change the VAT rate

  1. Admin, Billing: close the current rate for the code, then add a new rate under the same code starting when it takes effect (ManageTaxRules). Do not edit the old row. Rules need no change because they point at the code.

Tax a new kind of charge

  1. Add an AllocationType and set isTaxable() to true.
  2. In the quote builder, call TaxEngine::charge() with that fee type and add the result to a TaxBreakdown::of(); add only addedTotal() to the total.
  3. Add a fee-scope rule with the allocation type's value as scope_value.

Add a new scope

  1. Add the case to TaxScope with specificity() and requiresValue(); update TaxRuleResolver::scopeChain() and any caller of resolveFirst(); extend TaxEngineTest.
