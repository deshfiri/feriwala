Content Library module

Content written once (text, images, videos, links) and released to one or more products, shown to partners on each product's page. Staff author it; partners only read it.

Purpose

Staff (Content Manager, Product Manager, Admin) write marketing and instruction content once and release it to chosen products instead of repeating it per product. Released items appear in the partner catalogue product detail (Erp\CatalogController and the mobile catalogue controller load libraryContent and render it through ContentBlocks::present()). Related to, but separate from, the per-product update feed (ProductContent) in Catalog. Reflects §12 (partners never author catalogue content).

Key terms

Item
A title plus an ordered list of blocks, released to a set of products.
Block
One of text, image, video, link. Structured data, never HTML.
Release
Creating an item publishes it at once to every chosen product; there is no draft.
Library upload
A StoredFile with purpose content-library, public visibility.

Block shapes: text {text}; image {file_id, alt?, caption?}; video either {file_id} (uploaded) or {url} (https link), plus optional caption; link {url, label, description?}. Image types: jpeg, png, webp, gif, avif; video types: mp4, webm, ogg, quicktime (SVG deliberately excluded because it can carry script).

States & lifecycle

No status enum. An item is live from creation (published_at = now()) until soft-deleted. Editing changes what partners see immediately.

Actions & workflows

  • SaveContentLibraryItem::handle($actor, ?$item, $title, $blocks, $productIds): creating needs content_library.create, editing needs .edit. Requires a non-empty title, at least one block, and one or more existing products (all public ids must resolve). Blocks are rebuilt from allowed keys per type, unknown types throw; every file_id must be a content-library upload of the right mime kind; links must be full http/https URLs; a video block needs exactly one of file or URL. In a transaction it creates/updates the item and sync()s the products, then audits content_library.published or content_library.updated (before/after title, products, block count).
  • UploadContentLibraryFile: for image or video chosen in the editor before the item is saved; needs create or edit; stores via StoreManagedFile (public, no size cap set by the app; the web server limit still applies). Uploaded files are not deleted when an item is.
  • DeleteContentLibraryItem: needs .delete; audits content_library.removed with title and products, then soft-deletes.

Presentation: ContentBlocks::forEditor() returns stored blocks plus preview URL and mime; present() resolves files to URLs, drops missing files, and turns YouTube/Vimeo links into embed URLs (youtube-nocookie.com, player.vimeo.com); other video links are shown as plain links.

Permissions & scoping

Module content_library: view, create (release), edit, delete. Held by Admin, Content Manager and Product Manager. ContentLibraryPolicy::allows() refuses anyone with an account membership, whatever role they hold. Partners reach content only through the product page, which is itself gated by catalogue eligibility. The product page loads library content only when the viewer passes ContentLibraryPolicy::canView() in the admin editor (ProductController shows it with can-flags).

Money, ledger & audit effects

No money. Audit actions (module content_library): content_library.published, .updated, .removed.

Configuration

None specific. File storage follows the managed-storage configuration (Storage).

Rules, invariants & gotchas

  • Content is data, never HTML. Never render a block as markup; add new block types to ContentBlocks::TYPES, SaveContentLibraryItem::clean() and present() together.
  • There is deliberately no limit on blocks, text length or file size in the app (ContentBlocks::NO_LIMIT).
  • No draft step: an accidental save is public immediately.
  • Public files: uploaded images/videos are public; do not put private material in the library.
  • An item must always target at least one existing product.

How to…

  1. Add a block type: extend ContentBlocks (TYPES, present()), the match in SaveContentLibraryItem::clean(), the editor (pages/admin/content-library/form.tsx), the product detail renderers, and add tests.
  2. Allow another image type: add to ContentBlocks::IMAGE_TYPES (never SVG).
  3. Add an embed provider: extend ContentBlocks::embedUrl() with a strict host and id pattern.

Testing
