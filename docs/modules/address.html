Address module

One shared, polymorphic address book for business accounts and Suppliers. Each address ties to the Bangladesh location directory, freezes its place names at save time, has at most one default per owner and type, and is archived, never deleted.

Purpose

A BusinessAccount keeps business and operational addresses; a Supplier keeps registered, pickup and return addresses. One table (shared_addresses) serves both, resolved by owner_type plus owner_id (§31.3 self-scoping by an explicit owner column, not framework polymorphism). Consumers include damaged-item delivery (DamageDispatch, RequestDamageDelivery) and the partner/Supplier address screens. Do not confuse it with user_addresses (Account), the per-user address used for wholesale checkout snapshots.

Only ArchiveSharedAddress reaches archived, via transitionTo(), and it clears is_default. An archived address cannot be edited or made default (RuntimeException).

Actions & workflows

ClassBehaviour
SaveSharedAddressCreate or update. In a transaction: builds the attributes and resolves the snapshot from the validated location ids, then for an update locks the row and refuses if archived. New rows start active, not default. If makeDefault, then calls SetDefaultSharedAddress. The caller must already have validated the ids with ValidBdLocationHierarchy; the action does not.
SetDefaultSharedAddressLocks the row, refuses if archived, clears is_default on the owner's other addresses of the same type, sets this one.
ArchiveSharedAddressLocks, transitionTo(Archived), unsets default.
SharedAddressesForOwnerforOwner() (default first, then newest) and findForOwner($type, $ownerId, $publicId). The owner is always a parameter; the controller resolves it from its own guard.

Edit then default, in order: the save transaction commits before the default step runs, so a failure in the second leaves a saved, non-default address.

Permissions & scoping

  • SharedAddressPolicy (registered for SharedAddress) is the Client/Partner side only: viewAny needs a business account; view needs the address to belong to that account; create, update, archive, setDefault additionally need AccountPermission::UpdateAccount (owner only by default), "speaking for the business rather than working in it", the same bar as WebsitePolicy.
  • The Supplier side is never routed through a policy: Supplier controllers scope every query to the signed-in Supplier's own guard identity (D25). The guard boundary already refuses another Supplier's session.
  • Lookups by public id always include the owner pair in the query, so a guessed id from another owner returns nothing (§31.3).

Money, ledger & audit effects

None. These Actions write no audit entries. On account erasure, EraseAccount purges contact, address, landmark, postcode and snapshot columns of the owner's rows. A damaged-item dispatch address snapshot is locked by a database guard and is reported as retained.

Configuration

None.

Rules, invariants & gotchas

  • Archive, never delete; a default is never archived.
  • The snapshot is written once per save. A later rename or deactivation in the directory never rewrites an address on file; show location_snapshot for history and the relations for live editing.
  • Consumers that must keep what an address said at use time should store toSnapshot() output, not the foreign key.
  • Default uniqueness is per owner and type: a business may have a default business address and a default operational address.
  • Owner and public id cannot change after insert (database trigger).

How to…

Add an address type

  1. Add the case to ClientAddressType or SupplierAddressType (they feed allowedAddressTypes()).
  2. Add a migration changing shared_addresses_type_known to include the new value.
  3. Add labels in lang/en/address.php and lang/bn/address.php.

Add a new owner kind

  1. Add a case to AddressOwnerType and its allowed types; migrate the shared_addresses_owner_type_known check.
  2. Scope every read through SharedAddressesForOwner with the owner id from the controller's guard; write a policy or guard-scoped controller.

Save an address from a new screen

  1. Validate the four location ids with ValidBdLocationHierarchy and the E.164 mobile; check type with Rule::in($ownerType->allowedAddressTypes()).
  2. Call SaveSharedAddress::handle(...); authorize with the policy first.
