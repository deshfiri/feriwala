Location module

The Bangladesh administrative directory (Division, District, Upazila, Union) as bilingual reference data, with a pinned-source importer, cached cascading lookups for address forms and a public-id scheme for storefront delivery areas.

Purpose

Addresses (Address), bank branches (Bank) and storefront delivery areas all refer to one directory instead of free text. The data is bundled in the repo from a pinned upstream commit (see database/data/bangladesh-location/NOTICE.md) rather than fetched at runtime. Users: partners and Suppliers (address forms), storefronts (delivery area picker), the system (import). Spec: §39 (never send the whole directory on a page).

One bd_locations row of any level.

The upstream id (a string). Unique only within its parent, not globally; the English upstream file uses numbers and the Bangla one strings, so everything is cast to string.

States & lifecycle

A node is active or inactive. Nodes are never deleted: one missing from a later import is deactivated, and one that returns is reactivated by the upsert. Because the identity columns are locked, a node that would move under another parent is a different natural key: a new row is created and the old one deactivated.

BdLocationType: division → district → upazila (labelled "Thana / Upazila") → union. child() and parent() walk by enum order; sourceCollectionKey($locale) gives the upstream JSON key, e.g. districts_en.

Actions & workflows

ImportBdLocations::handle($mode)

  1. Loads the bundled en.json and bn.json from database/data/bangladesh-location/.
  2. Flattens each level, dedupes by type|source_id (first wins; later ones are reported as problems, never silently dropped), reports orphans (parent missing) and hierarchy disagreement between the two languages (missing counterpart, or different parent).
  3. Any problem, or mode validate, returns the report with no writes.
  4. dry-run runs the identical upsert inside a transaction that is always rolled back (a private DryRunRollback exception) and returns the counts.
  5. import commits updateOrCreate per node (parents first, so ids resolve), sets is_active = true for everything seen, deactivates every active node not seen, and appends a bd_location_imports row, all in one transaction.

The source URL, commit SHA, both checksums and license (MIT) are constants in the class. handleDecoded() takes decoded arrays so tests can prove duplicate, orphan and mismatch rejection without corrupting the real files.

Lookups

  • BdLocationChildren::topLevel() and childrenOf(type, parentSourceId) return {id, source_id, name_en, name_bn} sorted by English name, cached 1 day under bd_locations.v{importId}.{type}.{key}. A re-import changes the version so every key invalidates; nothing flushes by hand. One payload carries both languages.
  • DeliveryAreas::children($parent) / find($publicId): active children with has_children, capped at 1000 (MAX_RESULTS), identified by the natural key, never the database id.
  • ValidBdLocationHierarchy(BdLocationType): the field must be an active node of that level whose parent is the value already submitted in the level above's field (division_id, district_id, upazila_id), read from the request data via DataAwareRule.

Permissions & scoping

Reference data with no owner, so no self-scoping applies; the lookup routes sit behind ordinary authentication. There is no admin screen to edit locations and no permission for it.

Money, ledger & audit effects

None. The import writes no audit entry; bd_location_imports is its own record.

Configuration

No env or settings keys. Source data and its NOTICE.md live in database/data/bangladesh-location/. Cache driver follows the app's cache store (Redis).

Rules, invariants & gotchas

  • Never delete or edit identity columns (the database refuses). Rename = change name_en/name_bn; retire = is_active false.
  • A row referenced by an address that later becomes obsolete stays readable because addresses also freeze a location_snapshot.
  • source_id must be unique within a type for parent references to resolve at all; a repeat under another parent is rejected as a duplicate.
  • An import deactivates anything the file no longer contains, so a truncated data file would deactivate real locations. Run --mode=dry-run first and read deactivated.
  • Cache entries last a day but are version-keyed; a failed or rolled-back import does not bump the version.

How to…

Refresh the directory

  1. Replace the JSON under database/data/bangladesh-location/ and update NOTICE.md, then update the commit SHA and checksum constants in ImportBdLocations.
  2. php artisan bd-locations:import --mode=validate, then --mode=dry-run, then default.
  3. Re-run bd-banks:import if district names changed, since branches resolve districts by name.

Use the cascade in a form

  1. Validate with new ValidBdLocationHierarchy(BdLocationType::Division) and the three below it on division_id, district_id, upazila_id, union_id.
  2. Fetch options from locations.divisions and locations.children (route helpers via Wayfinder).

Expose areas to a new consumer

  1. Use DeliveryAreas::publicId() / find(); never expose bd_locations.id.

Testing

Pest group location: vendor/bin/pest tests/Feature/Location in its own schema, one suite at a time. Import tests feed arrays to handleDecoded().
