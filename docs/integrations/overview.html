Integrations overview

Everything under app/Integrations: payment gateways, SMS providers, couriers, store platforms, DNS and object storage. Each family has one contract, one manager that resolves a driver, credentials held in settings, and fakes for tests. Read this before adding a driver or changing how Feriwala talks to a third party.

How every family is built

The families share one shape so that adding a provider never changes the code that uses it (D7, D8):

Rule. Credentials are never in committed config, code or .env files for these families. They live encrypted in the settings table (payment, SMS, courier, R2) or in encrypted columns (store connections), are entered by an administrator, and never appear in a page prop, a log or an audit row. "Is it configured" is answered by names of missing keys, never values.

Rule. A driver declares only what has been implemented against the provider's own documentation. What a driver does not declare is refused rather than guessed at. A decline is a result, not an exception; only genuine faults (unreachable provider, malformed response) throw.

Payment gateways

Location: app/Integrations/Payment. Implements §26 and decisions D4 (currencies and exchange rates), D7 (gateway abstraction), D12 (Feriwala is merchant of record) and D36 (Partner-owned gateways, Model B). Settlement logic lives in app/Domain/Billing; this layer only talks to providers.

The contract

Contracts\PaymentGateway has these methods:

MethodPurpose
initiate(PaymentIntent): GatewayRedirectBegin a payment; returns the URL (and optional formFields when the gateway needs a POST).
handleCallback(Request): GatewayResultRead the browser's return request. Establishes identity only; the outcome is a claim until verified.
verifyWebhookSignature(Request): boolConstant-time, fail closed.
verify(string $gatewayReference): GatewayResultAsk the provider directly. The authoritative answer; nothing releases value without it.
status(string $reference): GatewayResultAsk what became of our transaction; used by reconciliation. Only called when StatusQuery is declared.
refund(RefundIntent): RefundResult, refundStatus(string): RefundResultOnly called when the matching refund capability is declared. A refund the provider has not settled is pending, never refunded.
name(), capabilities(), supports(), supportedCurrencies(), isSandbox()Identity and declared abilities. GatewayCapability cases: initiate, verify, webhook_signature, status_query, refund_full, refund_partial, refund_status.
isConfigured(), requiredConfiguration(), missingConfiguration()Names of keys, never values; drive the admin screen.

Four rules every driver holds to: never trust the browser; verify server-to-server before releasing anything; never throw for a declined payment; declare only what you implemented. Optional Contracts\TestsConnection::testConnection() authenticates against the provider and discards the result (implemented by EPS). Outcomes map onto GatewayOutcome (paid, pending, failed, cancelled); only paid releases value. GatewayResult keeps the gateway-reported amount apart from the requested one, because comparing them is how a tampered redirect is caught.

Abstract Gateways\Gateway supplies naming, mode, configuration answers, and refusing defaults (status(), refund(), refundStatus() throw GatewayCapabilityMissing). Abstract Gateways\GatewayCredentials reads payment.{gateway}.mode and payment.{gateway}.{mode}.{key} from settings; an unrecognised mode means sandbox; a missing credential throws GatewayUnavailable.

Per-driver notes that bite:

  • EPS is built from the EPS Merchant API Integration Guide v0.5 only: three calls on one host (/v1/Auth/GetToken, /v1/EPSEngine/InitializeEPS, /v1/EPSEngine/CheckMerchantTransactionStatus). Every request carries an x-hash computed here as base64(hmac_sha512(data, hash_key)): the hash of the username for the token call, of the merchant transaction id for the other two. Nobody pastes a hash or token. The guide documents no sandbox host and no IPN, so the base URL is a stored, validated setting (EpsCredentials::baseUrl(); official live host https://pgapi.eps.com.bd), and verifyWebhookSignature() refuses everything: nothing releases value except a direct status check. It needs a payer address and a numeric attempt reference (PaymentIntent::attemptReference, at least ten digits). Nothing sensitive is logged (never token, hash, credential, payer or payload).
  • Stripe verifies webhooks with the Stripe-Signature header (hash_hmac('sha256', timestamp.'.'.body, secret)). PayPal verifies through PayPal's own verification endpoint using the PAYPAL-TRANSMISSION-* headers.
  • Nagad is a configuration foundation only: its merchant guide is issued to registered merchants and an RSA signing scheme is not something to reconstruct, so it declares no capabilities and cannot take money.
  • Three providers do not sign notifications (shurjoPay's own guidance is to verify through its API). That is safe because a notification only says which payment to look at.

Stale comments. The docblock of PaymentGatewayManager::catalogue() and a comment in PaymentWebhookController still say "EPS and Nagad" declare nothing. EPS now declares initiate, verify and status_query; trust capabilities() and tests/Feature/Payment/ShippedGatewayStateTest.php, not those comments.

Registration, resolution and availability

  • config/payment.php maps a name to driver (class), enabled (the shipped default) and label. A provider with an empty driver is listed but unimplemented.
  • PaymentGatewayManager::driver($name) resolves from the container and caches per manager instance; it throws InvalidArgumentException for an unknown name and GatewayUnavailable for one with no driver. names() lists everything §26 names; implemented() those with a driver.
  • Enabled is a setting, not config: isEnabled() reads payment.{name}.enabled and falls back to the config default, so an administrator can switch it without a deploy. A newly added provider arrives disabled.
  • Available means implemented, able to verify, enabled and fully credentialled (catalogue() reports is_available; available() and availableFor(Currency) filter on it). No credential ever appears in the catalogue, only the names still missing.
  • scopedDriver($name, $mode, $credentials) builds a fresh driver bound to a Partner's own credentials (D36) by swapping the constructor argument named credentials for one backed by ScopedGatewaySettings. It is never cached, so a Partner's driver can never become the next caller's gateway. App\Domain\Billing\PartnerGatewayResolver chooses: activeVersionFor($website) for a new attempt, driverForPayment($payment) for everything after, which uses the version frozen on the payment.

FX and exchange-rate conversion

D4 (amended): the base ledger is Taka. App\Domain\Billing\ExchangeRates holds administrator-entered rates (setting payment.fx.rates, Taka per one unit, an exact decimal string with up to eight digits and six decimals; nothing fetches a rate). PaymentGatewayManager::chargeCurrencyFor($gateway, $paymentCurrency) returns the payment's own currency when the driver supports it; otherwise, for a Taka payment only, the first supported currency that has a rate; otherwise null and the gateway is not offered. A payment already in a foreign currency is never converted into another. Charging rounds the foreign figure up to the cent so Feriwala never collects less than it is owed; refunding rounds down so partial refunds cannot exceed what was charged. conversionNotice() gives the payer the currency, rate and charge before they choose. PaymentIntent::amount is what the gateway is asked for and originalAmount is the Taka amount owed. All of it is exact decimal (Money, bcmath), never a float.

Webhooks, return URLs and idempotency

RouteBehaviour
POST /webhooks/payment/{gateway} (webhooks.payment), POST /webhooks/payment/{gateway}/{payment} (webhooks.partner-payment)Webhook\PaymentWebhookController, throttled payment-webhooks (PAYMENT_WEBHOOK_RATE_LIMIT, default 120, per gateway and address). Verifies the signature where the driver has one, records a payment log row, queues SettleGatewayNotification, and always answers the same {"message":"Acknowledged."} so the endpoint cannot be used to ask which references exist. A Partner gateway's address names the payment, so its frozen version's credentials check the signature (D36).
Return routes checkout.return, checkout.cancelled, checkout.failed; website-orders.payment.return|cancelled|failedWhere the payer is sent back; they settle nothing. A gateway that POSTs the payer back reaches a stateless receiver first.

Billing\Jobs\SettleGatewayNotification runs on queue PAYMENT_QUEUE (default payments), 5 tries, backoff 30 s, 2 min, 10 min, 30 min. It is safe to run twice: SettlePayment takes a distributed lock and re-reads the payment inside it, returns early if already settled, and the job uses WithoutOverlapping. The retry schedule is ours, not the provider's. GatewayNavigation sends the payer to the gateway via Inertia::location() (a 302 would be followed by the XHR and fail on CORS) and refuses a redirect that is malformed, not https (except a local stub), or has embedded credentials.

Money invariants apply: every amount is a Money object; a payment that settles posts a ledger entry through the Billing and Wallet Actions in a transaction with locking and an idempotency key. See Billing and Wallet.

Adding a payment gateway

  1. Create app/Integrations/Payment/Gateways/<Name>/<Name>Credentials.php extending GatewayCredentials: gateway() returns the config name and requiredKeys() returns the credential key names.
  2. Create <Name>Gateway.php extending Gateway. The constructor must take the credentials object as a parameter literally named credentials and typed to your subclass, or scopedDriver() (Partner gateways) cannot rebind it. Implement credentials(), capabilities() and each declared operation; call requireConfigured() before dialling out. Override supportedCurrencies() if not BDT.
  3. Declare in capabilities() only what you implemented against the provider's own documentation. No Verify capability means the gateway can never be offered.
  4. Add an entry to config/payment.php with driver, enabled => false and label.
  5. Never touch PaymentWebhookController or the settlement flow; they know no provider names. Map the provider's status vocabulary onto GatewayOutcome in the driver.
  6. Add tests/Feature/Payment/<Name>GatewayTest.php modelled on an existing one, and update ShippedGatewayStateTest (it pins every gateway's shipped state and will fail until you do, deliberately). Check GatewayConfigurationTest too.
  7. Credentials are entered by an administrator at Admin, gateways (PaymentGatewayController); the screen renders its fields from requiredConfiguration(). Whether the screen needs any per-gateway label strings is not verified.

Testing: Http::fake() for provider calls (note that Http::fake() merges stubs; GatewayFlowTest explains the trap), Queue::fake() for settlement, and settings fixtures for credentials. Run with vendor/bin/pest tests/Feature/Payment or --group=payment.

SMS

Location: app/Integrations/Sms (§30). The contract is Contracts\SmsProvider: send(SmsMessage): SmsResult, balance(): ?string, name(), isConfigured(), requiredConfiguration(), missingConfiguration(). SmsMessage carries to, body, Locale, event and userId, and knows its segments() (Bangla is UCS-2, 70 characters per segment instead of 160). SmsResult has three shapes: accepted($reference, $cost), rejected($error, $code) (will refuse again: bad number, no balance) and failed($error, $code) (transient; retryable = true). A provider must not throw for a provider-side rejection.

NameDriverNotes
log (default)Providers\LogSmsProviderWrites to the sms log channel; recipient masked; the body is withheld in production because it is where one-time codes travel.
gennetProviders\GenNet\GenNetSmsProviderRequired keys base_url (must be https), api_token, sid; timeout SMS_GENNET_TIMEOUT (20 s). GenNetStatusCode maps its codes.
bulksmsbd, novasms, sslcommerz, twilionone (driver is null)Declared in config, shown in the admin catalogue as known but unbuilt.

Resolution. SmsProviderManager::driver(?string $name) returns a named driver or the active one. active() reads setting sms.provider, then SMS_PROVIDER (default log), and ignores a chosen provider that has no driver. isEnabled() is the global switch (setting sms.enabled, then SMS_ENABLED); canSend() needs it on, an implemented active provider, and credentials present. SmsServiceProvider binds SmsProvider through the manager (not a singleton, so a provider switch takes effect without a worker restart) and registers sms as a notification channel. Per-event switches live beside the notifications (SmsEventSwitch).

Credentials. SmsCredentials reads sms.{provider}.{key} from settings, encrypted, with no sandbox/live split. SmsGateway is the abstract base mirroring Gateway.

Delivery. Notification\Jobs\DeliverSmsMessage on queue SMS_QUEUE (default sms), 3 tries, backoff 60 s then 300 s, retrying only retryable results; a rejection is recorded and left alone. Turning SMS off also stops what is already queued.

Adding an SMS provider

  1. Add <Name>Credentials extending SmsCredentials (provider(), requiredKeys(); override missing() for extra validation as GenNet does for the https base address).
  2. Add <Name>SmsProvider extending SmsGateway; implement send() returning an SmsResult, never throwing for a rejection; call requireConfigured() first.
  3. Set the entry's driver in config/sms.php (replace the null).
  4. Tests: copy GenNetSmsProviderTest (Http::fake(), settings for credentials; tests/Feature/Notification/). The settings screen is Admin\SmsController; credentials are saved by ConfigureSmsCredentials.

Courier

Location: app/Integrations/Courier (§21, D8). The contract Contracts\CourierProvider: createShipment(Shipment), requestPickup(Shipment), fetchTrackingStatus(Shipment): ?OrderCourierStatus, cancelShipment(Shipment), verifyWebhookSignature(Request): bool, code(): CourierProviderCode. CourierProviderCode has manual, steadfast and pathao; pathao has no driver.

CodeDriverBehaviour
manualDrivers\ManualCourierDriverNo outbound calls: a person enters the tracking number and advances status; the shipment row is the record.
steadfastDrivers\SteadfastCourierDriver with Steadfast\SteadfastClient, SteadfastCredentials, SteadfastStatusBooking happens in BookSteadfastShipment before a shipment row exists (a network call must not run inside the creating transaction), so createShipment() does nothing. requestPickup() and cancelShipment() throw UnsupportedCourierOperation (no such endpoints are documented). Webhook auth is Authorization: Bearer <token> compared whole, in constant time, failing closed.
pathaononeSeeded as a disabled, credential-less provider row.

Registry. config/courier.php maps drivers (manual and steadfast) to classes. CourierManager::driver(CourierProviderCode) resolves from the container and throws for a code with no driver. Unlike payment, enabled is the seeded courier_providers.is_enabled row (isEnabled()), and isAvailable() means implemented and enabled. catalogue() lists every provider so the UI can name an unreachable one.

Steadfast credentials are settings keys courier.steadfast.api_key, secret_key, webhook_token, base_url (plus last-test markers). The base address is validated on every read: https only, and in production the host must be in courier.steadfast.allowed_hosts (portal.steadfast.com.bd), an SSRF guard for an administrator-typed value. Timeouts and polling are in config/courier.php (connect_timeout 5, timeout 20, poll batch 50, interval 600 s, error interval 1800 s).

Webhook. POST /webhooks/courier/steadfast (webhooks.courier.steadfast, Webhook\SteadfastWebhookController): bearer check first, then a 16 KB body cap, JSON only, five validated fields (consignment_id, invoice, status, cod_amount, updated_at), then ReceiveSteadfastWebhook. The body is never logged or stored; an unmatched or duplicate event answers like a processed one so the endpoint cannot be used to probe invoices. The token is rotated at admin route courier.steadfast.webhook-token (throttle 6 a minute).

Adding a courier

  1. Add a case to CourierProviderCode (with label) and a seeded courier_providers row via a migration.
  2. Write the driver implementing CourierProvider. Refuse operations the provider does not offer by throwing UnsupportedCourierOperation rather than pretending.
  3. Register it under drivers in config/courier.php. Put credentials in settings, never config.
  4. If the provider calls back, add a controller that authenticates before reading the body, caps its size, and answers thinly. Add a route under webhooks/courier/.
  5. Tests under tests/Feature/Courier/ (Http::fake(); see SteadfastBookingTest, which also covers the "uncertain booking is never booked again blind" case). Run vendor/bin/pest --group=courier.

Store platforms

Location: app/Integrations/Store (D29). Full behaviour is in External store; this section is the driver layer.

Contract. Contracts\StorePlatformDriver: verify(StoreEndpoint), fetchOrders(StoreEndpoint, int $sinceId, ?CarbonImmutable $updatedSince): StoreOrderPage, signatureIsValid(rawBody, lowercased headers, secret), webhookEventId(headers), readWebhook(payload): StoreWebhook, webhookEvents(). DFCOMMERCE driver. OutboundAddressGuard (SSRF protection)

Support\OutboundAddressGuard keeps calls to partner-supplied addresses off Feriwala's own network. addressFor($host) resolves through HostResolver (A and AAAA via dns_get_record; an IP literal resolves to itself), throws StorePlatformException::unreachable() if nothing resolves, requires every returned address to be public (isPublic(): PHP's no-private and no-reserved flags, IPv4-mapped IPv6 judged as the IPv4 it is, carrier-grade NAT 100.64.0.0/10 refused), throws addressRefused() otherwise, and returns the first address. The caller then pins the request to that address with CURLOPT_RESOLVE, disables redirects and sets short timeouts, so a DNS answer that changes between check and request cannot reach anywhere else. Support\StoreAddress::parse() accepts only https with a host and no embedded credentials, and reduces an address to the comparable host[:port].

The same guard protects the Website webhook sender (ManageWebhookEndpoint at save time, AttemptWebhookDelivery before every attempt). Anything in the ERP that calls an address a user typed must go through it.

DNS

Location: app/Integrations/Dns. Contracts\TxtRecordResolver::txtRecords(string $name): list<string> returns the TXT strings at a name, unquoted, and throws Exceptions\DnsLookupFailed when the lookup itself could not be made. SystemTxtRecordResolver uses dns_get_record($name, DNS_TXT) and joins split strings. It is bound as a singleton in WebsiteServiceProvider. A failed lookup is never read as "no record": the caller must neither mark a domain verified nor demote it. Its one consumer is custom-domain verification in ManageWebsiteDomainRouting (record _banij-verify.<domain>). Note this is separate from HostResolver (A/AAAA for the outbound guard). Tests bind TxtRecordResolver to a fake that states what the DNS holds (see WebsiteDomainRoutingTest).

Storage

Location: app/Integrations/Storage/R2Manager.php, with the domain side in app/Domain/Storage (see Storage). Cloudflare R2 is reached as an S3-compatible disk built on demand: R2Manager::diskConfig() returns an s3 disk config (region defaults to auto, path-style endpoint, the public domain as url, throw = true), disk() builds it with Storage::build() (so rotating a credential takes effect on the next call, with no config cache to clear), and testConnection() does a real round trip (listing the bucket root, which fails on a bad key, secret or bucket) and returns R2ConnectionTestResult, with AWS4-HMAC-SHA256 and Authorization fragments stripped from any error before it reaches a screen or audit log.

Credentials come from R2StorageSettings (entered under Settings, Storage, encrypted at rest), not from config/filesystems.php's static s3 disk or AWS_* variables, which remain only an emergency fallback a deploy can use. ManagedStorage::diskFor(StorageVisibility) and diskForLocal($name) are the one fork: R2 when R2StorageSettings::isAvailable(), otherwise the local public, private, kyc or supplier-media disk (FILESYSTEM_DISK, KYC_DISK_DRIVER, SUPPLIER_MEDIA_DISK_DRIVER, PRIVATE_DISK_DRIVER in config/filesystems.php). Nothing already written is moved when R2 is switched on; MigrateManagedFileToR2 and RunStorageMigration do that. Each file's row (stored_files) records its own disk, so product media URLs resolve from the row's disk.

There is no contract to implement here: to support another object store, extend R2Manager's role (a new manager building another disk) and teach ManagedStorage to choose it; raise it for approval first. Test with Storage::fake() and the R2 settings fixtures in tests/Feature/Storage.

Security and operations checklist for any integration

  • Anything an administrator or partner can type that the ERP will call must pass an outbound guard (OutboundAddressGuard, or an allow-list host as Steadfast does) and disable redirects.
  • Inbound webhooks authenticate before parsing, compare in constant time, cap body size where the provider allows, deduplicate on the provider's event id, and answer identically for known and unknown references.
  • Slow work goes to a queue (payments, sms, webhooks, stores/default); make sure a worker listens on each queue name you add or the work silently never runs.
  • Never log a token, signature, credential or payload. Reuse PaymentLogRedactor where headers are recorded.
  • Money from a provider is parsed as an exact decimal string and never passes through a float.
